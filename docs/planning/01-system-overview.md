## 1. Purpose
เอกสารฉบับนี้จัดทำขึ้นเพื่อกำหนดภาพรวม ขอบเขต วัตถุประสงค์ บทบาทผู้ใช้งาน โมดูลหลัก สถาปัตยกรรมระดับแนวคิด และกฎทางธุรกิจระดับสูงของ **Online Library Management System (ระบบจัดการห้องสมุดออนไลน์)** เพื่อใช้เป็นกรอบอ้างอิงและรากฐานสำคัญสำหรับการจัดทำเอกสารความต้องการของระบบ (Requirements), การออกแบบกระบวนการทำงาน (Workflows), โครงสร้างฐานข้อมูล (Database Design), สัญญาการเชื่อมต่อระบบ (API Contract), และหน้าจอระบบ (Frontend Pages) ในลำดับถัดไป

---

## 2. System Overview
**Online Library Management System** คือ เว็บแอปพลิเคชันสำหรับการบริหารจัดการทรัพยากรและการให้บริการของห้องสมุดยุคใหม่แบบครบวงจร ระบบถูกออกแบบมาเพื่ออำนวยความสะดวกให้แก่สมาชิกในการสืบค้นข้อมูลหนังสือ ตรวจสอบสถานะความพร้อม ยืม คืน และจองหนังสือผ่านช่องทางออนไลน์ได้อย่างรวดเร็วและโปร่งใส พร้อมทั้งสนับสนุนเจ้าหน้าที่ห้องสมุด (Librarian) และผู้ดูแลระบบ (Admin) ในการควบคุมสต็อกหนังสือ ติดตามรายการค้างส่ง คำนวณค่าปรับอัตโนมัติ จัดการคิวการจอง และวิเคราะห์ข้อมูลสถิติของห้องสมุดผ่านแดชบอร์ด

---

## 3. System Goals
1. **เพิ่มประสิทธิภาพการให้บริการของห้องสมุด:** สมาชิกสามารถค้นหาและทำธุรกรรมเกี่ยวกับหนังสือ (ยืม-คืน-จอง) ได้ด้วยตนเองอย่างสะดวก
2. **ลดภาระงานและการบันทึกข้อมูลที่ซ้ำซ้อน:** ระบบช่วยจัดการสถานะการยืม-คืน ตรวจสอบสำเนาหนังสือคงเหลือ และคำนวณค่าปรับเมื่อส่งคืนล่าช้าอย่างถูกต้อง
3. **จัดการคิวการจองทรัพยากรอย่างเป็นธรรม:** แจ้งเตือนและจัดสรรหนังสือให้แก่สมาชิกตามลำดับคิวเมื่อหนังสือพร้อมให้ยืม
4. **เพิ่มความโปร่งใสและแม่นยำของข้อมูล:** ติดตามสถานะของหนังสือและประวัติการทำรายการแบบเรียลไทม์
5. **สนับสนุนการตัดสินใจของผู้บริหาร:** นำเสนอข้อมูลสถิติการใช้งานหนังสือ ยอดการยืม-คืน และรายงานค่าปรับผ่าน Dashboard

## 4. System Scope

### 4.1 In Scope (ขอบเขตที่ระบบรองรับ)
- **ระบบยืนยันตัวตนและการกำหนดสิทธิ์ (Authentication & RBAC):** รองรับ 3 บทบาทหลัก (Member, Librarian, Admin)
- **ระบบสืบค้นและแสดงรายการหนังสือ (Book Catalog & Search):** ค้นหาตามชื่อหนังสือ ผู้แต่ง หมวดหมู่ ISBN พร้อมฟังก์ชันกรองและจัดเรียงข้อมูล
- **ระบบธุรกรรมการยืม-คืน (Borrowing & Returning Transactions):**
  - บันทึกการยืมหนังสือ ตรวจสอบความพร้อมของสำเนา และกำหนดวันส่งคืน (Due Date)
  - บันทึกการรับคืนหนังสือ ตรวจสอบวันที่ส่งคืนจริง และตรวจจับรายการเกินกำหนด (Overdue)
- **ระบบการจองหนังสือ (Book Reservation):** จองหนังสือที่ถูกยืมหมด จัดลำดับคิว และแจ้งเตือนเมื่อหนังสือพร้อมให้ยืม
- **ระบบประวัติและสถานะผู้ใช้ (Member History & Status):** ดูรายการที่กำลังยืม ประวัติการยืม-คืนย้อนหลัง และสถานะการจอง
- **ระบบคำนวณและติดตามค่าปรับ (Fine Management):** คำนวณค่าปรับอัตโนมัติกรณีส่งคืนล่าช้า และติดตามสถานะค่าปรับ
- **ระบบการแจ้งเตือน (Notifications):** แจ้งเตือนวันใกล้ครบกำหนดส่ง, แจ้งเตือนหนังสือเกินกำหนด, แจ้งเตือนเมื่อหนังสือจองพร้อมยืม
- **ระบบจัดการข้อมูลหลังบ้าน (Library Administration):** จัดการรายการหนังสือ หมวดหมู่ สมาชิก และสถิติภาพรวม

### 4.2 Out of Scope (สิ่งที่อยู่นอกขอบเขตในเฟสนี้)
- ระบบอ่าน E-Book หรือไฟล์ PDF ออนไลน์แบบเต็มรูปแบบ
- ระบบชำระเงินค่าปรับออนไลน์ผ่าน Payment Gateway / บัตรเครดิต (ในเฟสนี้เน้นการบันทึกสถานะการชำระผ่านเจ้าหน้าที่)
- ระบบส่ง SMS หรือระบบโทรศัพท์อัตโนมัติ (ใช้การแจ้งเตือนภายในเว็บแอปพลิเคชันหรืออีเมลจำลอง)
- การเชื่อมต่อกับ Hardware เฉพาะทางภายนอก เช่น ประตูสแกน RFID หรือเครื่องคืนหนังสืออัตโนมัติ (Book Drop Machine)
- ระบบจัดส่งหนังสือทางไปรษณีย์ถึงบ้าน (เน้นการรับ-คืนหนังสือที่เคาน์เตอร์ห้องสมุดหรือตามจุดบริการ)

## 5. Target Users
กลุ่มผู้ใช้งานเป้าหมายของระบบประกอบด้วย:
1. **นักเรียน/นักศึกษา/สมาชิกห้องสมุดทั่วไป:** ต้องการค้นหาหนังสือ ติดตามรายการยืม จองหนังสือ และตรวจสอบวันส่งคืน
2. **เจ้าหน้าที่บรรณารักษ์และฝ่ายบริการห้องสมุด:** ต้องการเครื่องมือจัดการรายการหนังสือ ตรวจสอบการยืม-คืน ดูแลคิวการจอง และคิดค่าปรับ
3. **ผู้ดูแลระบบและหัวหน้างานห้องสมุด:** ต้องการดูแลผู้ใช้งาน กำหนดนโยบาย/อัตราค่าปรับ และติดตามรายงานสถิติการใช้งาน

## 6. User Roles
ระบบกำหนดบทบาทและขอบเขตหน้าที่อย่างเคร่งครัด 3 ระดับ:

| Role | คำอธิบายบทบาท | สิทธิ์และหน้าที่หลัก |
| :--- | :--- | :--- |
| **Member** | สมาชิกผู้ใช้บริการห้องสมุด | ค้นหาหนังสือ, ดูรายละเอียด, ยืมหนังสือ, คืนหนังสือ, จองหนังสือ, ยกเลิกการจอง, ดูประวัติและค่าปรับของตนเอง, รับการแจ้งเตือน |
| **Librarian** | เจ้าหน้าที่บรรณารักษ์ | จัดการแคตตาล็อกหนังสือและหมวดหมู่, จัดการรายการยืม-คืน, จัดการคิวการจอง, บันทึกการรับชำระค่าปรับ, จัดการข้อมูลสมาชิกเบื้องต้น |
| **Admin** | ผู้ดูแลระบบสูงสุด | จัดการบัญชีผู้ใช้และสิทธิ์, กำหนดค่าระบบหลัก (System Settings / อัตราค่าปรับ / ระยะเวลายืม), ดูแล Dashboard สถิติภาพรวม และ Audit Log |

> **หมายเหตุ:** ห้ามเพิ่ม Role อื่นนอกเหนือจาก 3 บทบาทนี้โดยไม่ผ่านการอนุมัติ

## 7. Major System Modules
โครงสร้างโมดูลหลักระดับระบบประกอบด้วย 12 โมดูล:

1. **Authentication & Authorization Module:** จัดการการเข้าสู่ระบบ ออกจากระบบ และการตรวจสอบสิทธิ์ตามบทบาท (RBAC)
2. **Book Catalog & Management Module:** บริหารจัดการรายการหนังสือ ข้อมูลบรรณานุกรม หมวดหมู่ และสถานะของหนังสือ
3. **Book Search & Discovery Module:** ให้บริการค้นหา กรอง และจัดเรียงรายการหนังสือตามเงื่อนไขต่างๆ
4. **Borrowing Module:** จัดการกระบวนการยืมหนังสือ ตรวจสอบความพร้อมของหนังสือ กำหนด Due Date และบันทึกประวัติ
5. **Returning Module:** จัดการกระบวนการรับคืนหนังสือ ตรวจสอบวันส่งคืนจริง และส่งต่อข้อมูลไปยังโมดูลค่าปรับกรณีล่าช้า
6. **Reservation Module:** จัดการคิวการจองหนังสือ ตรวจสอบเงื่อนไขการจอง และการยกเลิกการจอง
7. **Fine Management Module:** คำนวณค่าปรับจากการส่งคืนเกินกำหนด บันทึกยอดค้างชำระ และสถานะการชำระค่าปรับ
8. **Notification Module:** ระบบแจ้งเตือนเหตุการณ์สำคัญ (เตือนก่อนครบกำหนด, เตือนเกินกำหนด, เตือนเมื่อหนังสือจองพร้อมรับ)
9. **Member Management Module:** บริหารจัดการโปรไฟล์สมาชิก ประวัติการใช้งาน และสถานะการเป็นสมาชิก
10. **Librarian Operations Module:** หน้าต่างการทำงานสำหรับเจ้าหน้าที่ในการจัดการหนังสือและธุรกรรมยืม-คืนหน้าเคาน์เตอร์
11. **Dashboard & Reporting Module:** รวบรวมและแสดงผลสถิติการยืม-คืน หนังสือยอดนิยม และสรุปยอดค่าปรับ
12. **System Administration Module:** จัดการผู้ใช้งานระบบ กำหนดค่าพารามิเตอร์ของระบบ และตรวจสอบความปลอดภัย

## 9. System Actors
1. **Member (สมาชิก):** ผู้ขอใช้บริการสืบค้น ยืม จอง และรับการแจ้งเตือน
2. **Librarian (เจ้าหน้าที่):** ผู้ปฏิบัติการดูแลรักษาข้อมูลหนังสือ รับคืนหนังสือ ตรวจสอบสภาพ และจัดการคิว
3. **Admin (ผู้ดูแลระบบ):** ผู้กำกับดูแลระบบ กำหนดสิทธิ์ และกำหนดค่านโยบายของระบบ
4. **System Scheduler / Background Job (ระบบอัตโนมัติ):** ทำหน้าที่ตรวจสอบวันครบกำหนด ส่งการแจ้งเตือน และปรับปรุงสถานะ Overdue อัตโนมัติ

## 10. System Boundaries (ขอบเขตความรับผิดชอบของระบบ)

### 10.1 สิ่งที่ระบบรับผิดชอบโดยตรง (Inside System Boundary)
- การบันทึกและรักษาความสมบูรณ์ของข้อมูลหนังสือ สมาชิก และประวัติการทำรายการ
- การคำนวณวันครบกำหนดส่งคืนและค่าปรับตามกฎเกณฑ์ที่กำหนด
- การอัปเดตสถานะหนังสือ (Available, Borrowed, Reserved, Maintenance)
- การจัดการคิวการจองและแจ้งเตือนสมาชิกเมื่อหนังสือว่าง
- การควบคุมการเข้าถึงข้อมูลตามสิทธิ์ (Data Privacy & Authorization)

### 10.2 สิ่งที่อยู่นอกความรับผิดชอบของระบบ (Outside System Boundary)
- การตรวจสอบสภาพความเสียหายทางกายภาพของตัวเล่มหนังสือจริง (เป็นการประเมินของเจ้าหน้าที่)
- การรับชำระเงินด้วยเงินสดหรือการออกใบเสร็จรับเงินทางภาษีอย่างเป็นทางการ
- การติดตามทวงถามหนี้หรือหนังสือภายนอกระบบทางกฎหมาย
- การจัดการความปลอดภัยทางกายภาพของอาคารห้องสมุด

## 11. Major Business Concepts (แนวคิดทางธุรกิจระดับสูง)

- **Book (รายการหนังสือ/บรรณานุกรม):** ข้อมูลเชิงวิชาการของหนังสือ เช่น ชื่อเรื่อง, ผู้แต่ง, สำนักพิมพ์, ISBN, หมวดหมู่, เรื่องย่อ
- **Book Copy (สำเนาหนังสือ/เล่มจริง):** แนวคิดเชิงกายภาพของหนังสือแต่ละเล่มที่มีรหัสประจำตัวเฉพาะ เพื่อติดตามว่าเล่มใดว่าง เล่มใดถูกยืม หรือชำรุด *(วิเคราะห์ในระดับ Concept ยังไม่ใช่การออกแบบ Table)*
- **Borrowing Transaction (รายการยืม):** ข้อมูลการยืมหนังสือของสมาชิก ระบุวันยืม วันครบกำหนดส่ง (Due Date) วันที่ส่งคืนจริง และสถานะ
- **Return Transaction (รายการคืน):** กระบวนการสิ้นสุดการยืม มีการบันทึกวันที่คืนจริงและประเมินสถานะล่าช้า
- **Reservation Queue (คิวการจอง):** รายการสมาชิกรอรับหนังสือที่ถูกยืมอยู่ โดยจัดลำดับแบบเข้าก่อนได้ก่อน (First-Come, First-Served)
- **Due Date (วันครบกำหนดส่ง):** วันที่คำนวณจากวันที่ยืมบวกด้วยระยะเวลาที่ได้รับอนุญาตให้ยืม
- **Overdue (ภาวะเกินกำหนดส่ง):** สภาวะที่หนังสือยังไม่ถูกส่งคืนหลังจากพ้น Due Date
- **Fine (ค่าปรับ):** จำนวนเงินที่คำนวณจากจำนวนวันที่เกินกำหนดคูณด้วยอัตราค่าปรับต่อวัน
- **Notification (การแจ้งเตือน):** ข้อความหรือสัญญาณเตือนเหตุการณ์สำคัญไปยังผู้ใช้งาน

---

## 12. High-level Business Rules (กฎทางธุรกิจระดับสูง)
1. **การตรวจสอบสถานะก่อนยืม:** สมาชิกสามารถยืมหนังสือได้เฉพาะเล่มที่มีสถานะพร้อมให้ยืม (Available) และจำนวนคงเหลือต้องมากกว่า 0
2. **การรักษาสต็อกไม่ให้ติดลบ:** การยืมหนังสือต้องตัดยอดคงเหลืออย่างถูกต้อง และสต็อกต้องไม่ติดลบในทุกกรณี
3. **การจำกัดสิทธิ์การยืม:** สมาชิกต้องมีสถานะปกติ (Active) และไม่มีรายการค้างส่งหรือยอดค่าปรับค้างชำระเกินกำหนดที่นโยบายระบุ
4. **การจองหนังสือ:** อนุญาตให้จองได้เฉพาะหนังสือที่ไม่มีสำเนาพร้อมให้ยืมในขณะนั้น และสมาชิก 1 คนจองหนังสือเล่มเดียวกันซ้ำไม่ได้
5. **การคิดค่าปรับ:** ค่าปรับคำนวณจากวันที่ส่งคืนจริงเปรียบเทียบกับ Due Date โดยการคำนวณต้องทำที่ Backend เป็น Source of Truth เสมอ
6. **การเข้าถึงข้อมูลตามสิทธิ์:** สมาชิกเข้าถึงได้เฉพาะข้อมูลส่วนตัวและประวัติของตนเอง ส่วนเจ้าหน้าที่และผู้ดูแลระบบสามารถเข้าถึงตามขอบเขตความรับผิดชอบ

---

## 13. System Constraints (ข้อจำกัดของระบบ)
- **Tech Stack Constraints:** ต้องทำงานบน React 18, Node.js 20 LTS, Express 4, MySQL 8 และ Docker ตามที่ได้รับอนุมัติ
- **Single-container Deployment:** การ Deploy บน Railway ต้องรองรับสถาปัตยกรรมแบบ Single-container Multi-stage Build โดยไม่มี Nginx แยก
- **Data Integrity:** ต้องรองรับ Transaction Management เพื่อป้องกันความผิดพลาดของข้อมูลเมื่อมีผู้ใช้งานยืมหรือจองพร้อมกัน (Concurrency)
- **Language & Encoding:** ต้องรองรับภาษาไทยอย่างสมบูรณ์บนมาตรฐาน `utf8mb4`

---

## 14. Assumptions (ข้อสมมติฐานในการวิเคราะห์)
1. สมาชิกทุกคนต้องมีบัญชีและเข้าสู่ระบบก่อนทำรายการยืมหรือจองหนังสือ
2. การคำนวณวันครบกำหนดส่ง (Due Date) ในเบื้องต้นจะนับรวมวันหยุด *(Requires Confirmation)*
3. อัตราค่าปรับและระยะเวลาการยืมเริ่มต้นจะถูกกำหนดเป็นค่ามาตรฐานระบบ และ Admin สามารถปรับแต่งได้ภายหลัง
4. ระบบการแจ้งเตือนในระยะเริ่มต้นจะแสดงผลผ่าน Web Interface / In-app Notification เป็นหลัก

## 15. Risks & Mitigation (ความเสี่ยงระดับระบบ)

| ความเสี่ยง | ผลกระทบ | แนวทางป้องกันเชิงสถาปัตยกรรม |
| :--- | :--- | :--- |
| **Concurrent Borrowing (การยืมพร้อมกัน)** | หนังสือเล่มสุดท้ายถูกยืมซ้อน, สต็อกติดลบ | ใช้ Database Transactions และ Record Locking ที่ Backend |
| **Duplicate Reservation (การจองซ้ำ)** | สมาชิกจองหนังสือเล่มเดิมหลายครั้ง เกิดการแย่งคิว | กำหนด Unique Constraint และตรวจสอบประวัติการจองที่ยัง Active |
| **Fine Calculation Inconsistency** | การคำนวณค่าปรับผิดพลาด ไม่ตรงกัน | ให้ Backend เป็น Single Source of Truth สำหรับการคำนวณค่าปรับ |
| **Notification Failure** | สมาชิกไม่ได้รับแจ้งเตือน คืนหนังสือล่าช้า | ออกแบบระบบแจ้งเตือนแบบ In-app บันทึกลง Database พร้อม Flag สถานะการอ่าน |
| **Unauthorized Data Access** | สมาชิกดูข้อมูลหรือประวัติของสมาชิกคนอื่น | บังคับใช้ Resource Ownership Validation ใน Middleware |

## 16. Dependencies (ความสัมพันธ์ระหว่างโมดูล)
- **Borrowing Module** พึ่งพา **Authentication**, **Book Catalog (Availability)**, และ **Member Status**
- **Returning Module** พึ่งพา **Borrowing Transaction** และเชื่อมต่อไปยัง **Fine Management**
- **Reservation Module** พึ่งพา **Book Catalog**, **Borrowing Status**, และส่งต่อสถานะไปยัง **Notification**
- **Fine Management Module** พึ่งพา ข้อมูลวันส่งคืนจริงจาก **Returning Module**
- **Dashboard & Reports** พึ่งพา ข้อมูลสถิติจากทุกโมดูลธุรกรรม

## 19. Summary
ระบบ **Online Library Management System** มีเป้าหมายเพื่อสร้างระบบจัดการห้องสมุดที่มีประสิทธิภาพ รวดเร็ว และโปร่งใส โดยครอบคลุมกระบวนการตั้งแต่การค้นหา การยืม การคืน การจองหนังสือ การแจ้งเตือน และการคำนวณค่าปรับ ภายใต้สถาปัตยกรรม React 18, Node.js 20, MySQL 8 และ Docker โดยเอกสารภาพรวมระบบฉบับนี้พร้อมใช้เป็นฐานรากในการจัดทำเอกสารข้อกำหนดความต้องการ (Requirements Specification) ในลำดับต่อไป
